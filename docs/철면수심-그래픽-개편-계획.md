# ☀ 철면수심전용 그래픽 개편 계획 — 맵 · 구조물 · 이펙트 (2026-10-17)

사용자: **"어두운 버전은 별로 필요없어. 철면수심전용 버전에서만 그래픽 작업으로 더 낫게 해주고 맵이나 구조물의 퀄리티를 높이고 싶어"** · **"three.quarks(이펙트 손맛)도 적용할 계획을 세워줘 — 오늘은 계획만 모두 문서로 작성하고 다음에 이어갈 수 있도록"**.

> 조사 문서다. **게임 코드는 아직 한 줄도 바꾸지 않았다**(이번 커밋은 이 문서 · HANDOVER · 사진 도구 `tools/gallery.js` 뿐).
> 다음 세션은 **9장 "다음 세션 시작하는 법"** 부터 읽는다.

## 0. 결론 · 범위 (먼저 읽기)

- **☀ 철면수심전용(`skin === 'bright'`)만 바꾼다.** 🌙 공포스러움은 지금 그대로 둔다(지우지 않는다 · 고치지 않는다). 코드에서는 늘 `isBright()` 가지로 나눈다.
- **화면만의 일.** sim(`src/core/`) · 맵 모양 · 충돌 · 스킬 판정 · 락스텝 · 세이브는 건드리지 않는다. 그림이 충돌과 어긋나지 않게 **보이는 것은 지금 타일 자리 · 크기 안에** 둔다.
- 순서(체감이 큰 것부터): **A 빛 · 톤 매핑 → B 바닥 → C 벽 · 구조물 → D 놀이터 랜드마크 → E three.quarks 이펙트**. 한 단계 = 한 판(커밋 · 푸시 · 배포) · 단계마다 사용자에게 전후 사진을 보여 주고 다음으로 간다.
- 받을 것: **E 단계의 `three.quarks`(npm · MIT) 하나**. A ~ D 는 지금처럼 **코드로 그린다**(Blender 는 D 단계의 선택지 — 7장).
- 성능 규칙(GUIDE 11장 "가볍게")은 그대로: 4인 · 괴물 100 마리에서 재고 넣는다 · 점광원 16 상한 · 새 재질은 `queueWarm` / `compileAsync` · 이펙트 재질은 dispose 하지 않고 다시 쓴다.

## 2. 원칙

1. **화면만.** 바닥 · 벽 · 소품 · 이펙트는 `src/render3d/` 와 `src/game/skinThemes.ts` 에서 끝낸다.
2. **같은 맵이면 모든 브라우저에서 같은 모습** — 지금처럼 타일 좌표 해시(`hash(tx, ty, salt)`)로 정한다(이펙트는 예외 — 각자 그린다).
3. **읽기 쉬움이 먼저.** 바닥은 캐릭터 · 괴물 · 범위 예고(빨강 · 초록 · 보라 — GUIDE 11장 "범위의 색")보다 **채도 · 대비를 낮게**. 바닥에 빨강 · 진한 초록 큰 면을 쓰지 않는다(범위 예고와 헷갈린다).
4. **충돌과 겉모습을 맞춘다.** 벽은 그 타일 칸 안, 장애물은 한 칸 안. 높이는 카메라(55° 내려다봄)에서 뒤의 캐릭터를 가리지 않게 — 벽 2.6 · 랜드마크 2.8 넘지 않는다.
5. **그리기 호출 · 셰이더.** 종류마다 `InstancedMesh` 하나(지금 `inst()` · `put()`). 새 재질은 지역에 들어갈 때 미리 컴파일되는지(`renderer.gl.info.programs.length` 가 판 도중 늘지 않는지) 본다.
6. **자동 화질.** 낮은 단계에서는 바닥 무늬 덧그림 · 랜드마크 디테일 · 입자 수를 줄인다(세션 `gfx.level`).

## 4. B 단계 — 바닥 (큼 · 체감 가장 큼)

### 4.1 방식

- 지금처럼 **맵 전체 캔버스 한 장**(`paintFloorSteps` — 타일당 24px · 마을에서 나눠 그린다)에 **배치 무늬**(선 · 칸 · 길 · 무늬)를 그린다. 밝게는 `look.floor` 대신 **맵 번호별 바닥 종류**(`BRIGHT_FLOOR[map.id]`)로 고른다.
- 타일당 24px 은 가까이서 흐리다 → 해상도를 올리지 않고(메모리) **작은 반복 결 텍스처**(128px — 모래 알갱이 · 나무 결 · 잔디 결 · 타일 유약)를 바닥 재질에 한 장 더 곱한다. `onBeforeCompile` 로 `vMapUv * vec2(map.w, map.h) * k` 반복 · `customProgramCacheKey` · 셰이더 미리 컴파일. 결 텍스처는 종류마다 하나(코드로 그린다).
- 점 무늬(`arc` 세 개 / 칸)는 밝게에서 **없앤다.** 변화는 큰 얼룩(부드러운 잡음 — `paintOutside` 의 `noise`)으로 아주 옅게.
- 풀 잎(`grass`)은 밝게에서 **실외만 · 반으로**, 실내 · 대기실은 없앤다. 대신 실외 일부를 **작은 꽃**(꽃잎 다섯 + 노란 가운데, 인스턴스)으로.
- 구석 그늘(벽 · 상자에 닿은 변)은 그대로 둔다(벽이 서 보이게 — 지금도 밝게 0.55배).

- 벽 높이 · 자리는 지금(`look.wallH` · 칸 가운데) 그대로. 맵 밖 테두리(바닥과 닿지 않은 벽)는 지금처럼 안 그린다.
- 무너진 모서리(`rubble`)는 밝게: 흩어진 작은 블록 그대로 · 돌기 붙임.

### 7.1 왜 · 무엇

- `three.quarks` — three.js 용 입자 · VFX 엔진. **MIT** · 최신 **0.17.1**(2026-05-21) · `peerDependencies: three >= 0.182` → **지금 r185 와 맞는다**(npm 으로 확인). 의존성 `quarks.core`. 저장소 Alchemist0823/three.quarks(⭐1k · 2026-05 업데이트).

- 시각 편집기(three.quarks-editor · JSON 내보내기)가 있다 — 편집기 라이선스는 **확인 못 함** → 처음엔 **코드로 이미터를 정의**한다(Claude 가 쓰기 쉽고 git 으로 보기 쉽다).

### 7.2 범위 · 원칙

- **☀ 철면수심전용에서만 켠다**(사용자 방향). 🌙 은 지금 이펙트 그대로 — 같은 호출 자리에서 `isBright()` 로 나눈다. 나중에 사용자가 원하면 🌙 에도.
- **판정과 무관** — 이펙트는 화면만. 락스텝 · 해시 그대로.
- **시계**: `BatchedRenderer.update(dt)` 의 dt 는 **게임 프레임의 dt**(렌더러가 받는 것)를 넘긴다 — 소개 영상(`tools/trailer.js`)은 가상 시계로 오프라인 렌더하므로 실제 시간을 쓰면 영상이 어긋난다.
- **미리 컴파일**: 이미터 종류마다 재질이 생긴다 → 시작 준비(`prepareStart`)에서 이미터 견본을 한 번씩 보이게 해 `compileAsync`(HANDOVER ⚠ 셰이더 비동기). 이미터는 **풀로 다시 쓴다**(dispose 금지 — 셰이더가 지워져 다시 컴파일된다).
- **텍스처 아틀라스 하나**(512 — 별 · 하트 · 원 · 색종이 · 연기 · 빛점 · 음표 · 십자 …)로 재질 수를 줄인다 → 묶음(그리기 호출) 수 = 재질 × 블렌딩 조합 수. 목표 **묶음 8 ~ 12 개**.
- **예산**: 화면 동시 입자 **2,500 개 상한**(모든 이미터 합 — 넘치면 오래된 것부터 / 새 것 줄임) · 자동 화질 1 단계 절반 · 2 단계부터 꼭 필요한 것만(타격 · 처치). 4인 · 괴물 100 마리 · 스킬 난사 장면에서 GPU · CPU 프레임을 잰다(`__bd.gfx()` · `__bd.gpu()` · `renderer.info`).
- 기존 FxHost(`glow` · `puff` · `impact` · `light` · `shake`)는 그대로 두고, quarks 쪽은 새 모듈 `src/render3d/quarksfx.ts`(이름 예)에서 **프리셋 함수**(`burst('pop', x, y, z, color)` 같은)로만 부른다 → 갈아 끼우기 · 되돌리기가 쉽다.
