# 실사 그래픽 — 무료 에셋과 이 게임에 붙이는 방법

> 작성 2026-09-19 · 대상 v0.25.0 (three r185 · Vite · GitHub Pages)
> 조사 문서다. 코드는 아직 한 줄도 바꾸지 않았다.
> 라이선스는 2026-09-19 에 각 사이트의 라이선스 페이지를 직접 읽고 적었다. 직접 확인하지 못한 것은 **(확인 못 함)** 으로 표시했다.

## 0. 결론 · 추천 (먼저 읽기)

- **쓸 곳은 두 곳이면 충분하다: Poly Haven 과 ambientCG.** 둘 다 CC0 이다. 공개 저장소에 올려도 되고, 출처 표기도 의무가 아니다.
- **실사로 바꿀 것은 "배경"뿐이다.** 바닥·벽·장애물의 겉면(텍스처)과 큰 소품 몇 개.
- **캐릭터(오리)와 몬스터는 지금 그대로 둔다.** 팬게임의 얼굴이고, 어두운 실사 배경 위에서 오히려 더 잘 보인다(6장).
- **모양은 코드, 겉면만 실사.** 지금 코드가 만든 벽 블록·관·바위에 실사 텍스처를 입히는 것이 가장 싸고 효과가 크다. 모델(GLB)은 통·상자처럼 큰 소품 몇 개만.
- **기본은 꺼 둔다.** ESC 메뉴에 "실사 텍스처(실험)" 켜기/끄기를 둔다. 끄면 지금 모습 그대로다.
- **한 지역부터.** 1막 "지하 묘지"(맵 `crypt` — 지역 4·5·7·8 네 곳이 쓴다)의 바닥 하나로 시작해 재고, 괜찮으면 넓힌다.
- **첫 화면 추가 다운로드는 0 MB.** 켠 사람만, 그 막에 들어갈 때 받는다. 막 하나 3~5 MB, 4막 전체 20 MB 이하가 목표다.
- **쓰지 않을 것:** Fab/Quixel Megascans · Textures.com · ShareTextures · Mixamo · Sketchfab 의 유료(Standard/Editorial) 라이선스. 공개 저장소에 원본 파일이 올라가는 순간 약관 위반 소지가 있다(2장).
- **먼저 할 일:** GUIDE 11장에 "외부 모델·이미지·음원 없음 — 전부 코드로 조립한다" 는 제약이 있다. GUIDE 15장 규칙대로 **이 제약을 바꿀지 사용자가 먼저 정한다.** 정하면 8장 순서대로 작은 커밋으로 간다.

| 돌벽 | `buildDark()` 120행 | `BoxGeometry(1,1,1)` 인스턴스를 높이만큼 늘림 + 인스턴스 색 | 같은 인스턴스에 돌 텍스처. 높이 늘림으로 벽돌이 늘어나는 점 주의 |
| 바위·나무·목책·천막 | 143~215행 | 이십면체·원뿔·원기둥 + 단색 | 바위·나무껍질·천 텍스처 |
| 장애물(상자 타일) | 217~258행 | 관·통·도마·돌무더기를 원시 도형으로 | 통·상자는 GLB 로, 관·돌은 도형 + 텍스처 |
| 소품 | 260~297행 | 뼈·해골·양초·풀·묘비·버섯 (밟히지 않는 장식) | 화면에서 10~20px 이라 **그대로 둔다** |
| 인스턴스 도우미 | `inst()` · `put()` (93·102행) | 종류마다 `InstancedMesh` 한 개 = 그리기 호출 한 번 | 그대로 쓴다. 지오메트리·재질만 바꿔 넣는다 |

| 렌더러 | `renderer3d.ts` 222~247행 | WebGL2 · ACES 톤매핑 · PCF 부드러운 그림자(해 2048) · 안개 34~70 · 플레이어 등불 4개 | 품질 옵션에서 dpr·그림자 조절 |
| 지역 바꾸기 | `Renderer3D.setMap()` (281행) ← `session.ts` `syncView()` (502행) | 동기 함수. 곧바로 새 세계를 만든다 | 텍스처는 비동기로 받아 **나중에 갈아 끼운다** |
| 캐릭터 | `character3d.ts` | 달걀형 몸통 + 얼굴 텍스처, 뼈대 없음, `MeshLambertMaterial` | 그대로 |
| 몬스터 | `monsters3d.ts` | 부품별 `InstancedMesh` — 100마리여도 종류당 6~8 호출 | 그대로 |

**지역 ↔ 맵 ↔ 스타일** (world.ts 지역 표 · maps.ts)

| 막 | 맵 id (스타일) | 쓰는 지역 |
|---|---|---|
| 1막 | town1(town) · fields(fields) · cave(cave) · **crypt(crypt)** · cathedral(cathedral) · butchery(butchery) | 0~9. crypt 는 4·5·7·8 |
| 2막 | town2(town) · forest(forest) · swamp(forest) · hollow(cave) · nest(cave) | 10~18 |
| 3막 | town3(town) · sewer(crypt) · cistern(cave) · ruins(cathedral) · rite(cathedral) · archive(crypt) · wardroom(butchery) | 19~27 |
| 4막 | town4(town) · rift(fields) · ashen(fields) · pit(cave) · maze(crypt) · stair(cathedral) · throne(butchery) | 28~35 |

- 맵 id 하나는 한 막에만 나온다. 그래서 **"막 단위로 받기"** 가 깔끔하다.
- 하수도(sewer)·심연(rift·ashen·pit)은 따로 스타일이 없다. 색만 다른 crypt·fields·cave 다. 실사 재질은 맵 id 로 골라야 하수도는 이끼 벽돌, 심연은 탄 땅이 된다.

### 2.2 출처별 메모

**Poly Haven** — https://polyhaven.com/license (확인함)
- 모든 에셋이 CC0. 상업 이용 가능, 표기 필요 없음, 재배포 가능("include them when sharing your own work").
- 텍스처마다 1K·2K… JPG/PNG/EXR. `Diffuse` · `nor_gl`(OpenGL 노멀) · `nor_dx` · `Rough` · `AO` · **`arm`(AO·거칠기·금속을 한 장에)** 을 따로 받을 수 있다.
- 모델은 glTF(+bin+텍스처)로 받는다. 1K 판 크기를 API 로 확인했다(3.2 표).
- 공개 API(`https://api.polyhaven.com/assets?t=textures`)로 이름을 확인했다. 이 문서의 이름은 전부 실제로 있는 것이다.

**ambientCG** — https://docs.ambientcg.com/license/ (확인함)
- CC0 1.0. "You can include the raw files in your project, for example a video game."
- 표기는 권장. 권장 문구: `Created using <asset name> from ambientCG.com, licensed under the Creative Commons CC0 1.0 Universal License.`
- 1K-JPG 압축 파일이 재질 하나에 약 5 MB(노멀 DX/GL·변위·AO 등 전부 들어 있음). 필요한 3장만 골라 쓴다.

**Quaternius** — https://quaternius.com/faq.html (확인함)
- "All models are under the CC0 License." 표기 필요 없음.
- Modular Dungeon Pack · Ultimate Modular Ruins Pack · Fantasy Props MegaKit 등. **로우폴리 양식화**라 실사 목표와 다르다.

**Kenney** — https://kenney.nl/support (확인함)
- "all game assets on the asset pages are public domain licensed (CC0)". 로고만 쓰지 말 것.
- Graveyard Kit(https://kenney.nl/assets/graveyard-kit) 도 CC0 (확인함). 담긴 모델 종류·파일 형식은 (확인 못 함). 양식화.

**KayKit Dungeon Remastered** — https://kaylousberg.itch.io/kaykit-dungeon-remastered (확인함)
- 무료판 CC0, 200+ 모델, FBX·glTF·OBJ. 유료판(Extra·Source)도 있다. 양식화.

**Sketchfab** — https://sketchfab.com/licenses (확인함)
- 이 페이지는 **유료 Standard/Editorial** 약관이다. 2.2(b)·(h): 제3자가 파일을 "stand-alone" 으로 받거나 뽑아낼 수 있게 두면 안 된다 → 웹 게임·공개 저장소와 맞지 않는다.
- 무료 모델은 모델 페이지에 적힌 **CC 라이선스**를 따른다. CC0·CC-BY 만 쓴다.
- 2026-08-12 Epic 이 Sketchfab·ArtStation 을 KitBash 에 팔았다(https://www.gamedeveloper.com/business/epics-sells-artstation-and-sketchfab-to-kitbash, 확인함). 무료 내려받기는 아직 된다는 제3자 안내가 있다(https://app.cinevva.com/guides/game-assets-guide). **앞날은 모른다 → 쓸 것은 받아서 보관하고, 받을 때 라이선스 화면을 저장해 둔다.**
- 내려받기에 계정이 필요한지는 (확인 못 함).

**OpenGameArt** — https://opengameart.org/content/faq (확인함)
- 허용 라이선스: CC0 · CC-BY · CC-BY-SA · GPL · OGA-BY.
- 권장 표기: `"Asset name" by author name licensed License(s): [asset url]`. 게임 파일과 화면 크레딧 둘 다에 넣으라고 권한다.
- 실사 3D 는 드물다(의견).

**Fab / Quixel Megascans** — https://www.fab.com/eula · https://quixel.com/license (확인함)
- Megascans 는 이제 대부분 유료다. 무료는 약 1,500개(quixel.com FAQ).
- Fab 표준 라이선스는 Unreal 밖에서도 쓸 수 있다. 그러나:
  - 4(c): 프로젝트를 배포할 때 **최종 사용자가 콘텐츠를 프로젝트 밖으로 뽑아 쓰지 못하게 제한해야** 한다. 웹 게임은 텍스처 파일이 그대로 내려받아진다.
  - 5(a): 협업자에게 **비공개 저장소**로만 공유할 수 있다. 공개 GitHub 저장소는 안 된다.
  - 6(a): GPL·CC-BY-SA 콘텐츠와 섞으면 안 된다.
  - Epic 계정이 필요하다(8(c)).
- → **이 프로젝트(공개 저장소 + GitHub Pages)에는 쓰지 않는다.** Fab 안의 CC-BY 콘텐츠는 CC-BY 조건을 따르지만, 섞이면 헷갈리므로 피한다.

**Textures.com** — https://www.textures.com/support/faq-license (확인함)
- 게임에 쓰는 것은 된다. 무료 계정으로 받은 것도 된다.
- 그러나 "it is not allowed to release our images under Open Source licenses", 자기 웹사이트에 올리는 재배포도 금지. 공개 저장소에 원본이 올라가는 구조와 맞지 않는다 → **쓰지 않는다.**
- 무료 계정의 하루 크레딧·해상도 한도는 (확인 못 함).

**ShareTextures** — https://www.sharetextures.com/p/license (확인함)
- "CC0" 라고 하지만 자체 조건이 붙는다: 서면 허락 없이 다른 사이트·모음에 재배포 금지, 자동 내려받기·핫링크 금지.
- 공개 저장소에 올리면 걸릴 수 있다 → **쓰지 않는다**(쓰려면 허락을 먼저 받는다).

**Mixamo** — Adobe 공식 FAQ 글 https://community.adobe.com/questions-696/mixamo-faq-licensing-royalties-ownership-eula-and-tos-589400 (확인함)
- 상업·비상업 모두 로열티 없이 쓸 수 있고 표기도 필요 없다.
- 그러나 "the only thing you can't do is distribute the raw character and animation files". 공개 저장소에 FBX/GLB 원본이 그대로 올라간다 → 걸린다.
- 게다가 사람 뼈대용이라 뼈대 없는 오리 리그에는 붙지 않는다. Adobe 계정도 필요하다.
- helpx.adobe.com 의 FAQ 원문은 접속이 막혀(403) (확인 못 함). 위 공식 커뮤니티 글로 대신 확인했다.

**비상업(NC)·동일조건(SA) 라이선스는 피한다.** 지금은 무료 팬게임이라 NC 도 되지만, 나중에 후원 등이 붙으면 문제가 된다. SA 는 고친 파일에도 같은 라이선스를 붙여야 해서 관리가 번거롭다.

## 3. 이 게임에 맞춘 후보 목록

이름은 전부 Poly Haven API · ambientCG API 로 **실제로 있는지 확인했다**.
주소 형식: Poly Haven = `https://polyhaven.com/a/<이름>` · ambientCG = `https://ambientcg.com/view?id=<이름>`.
어느 것을 고를지는 **1K 로 받아 게임 안에서 보고** 정한다(같은 이름이라도 어두운 조명에서 느낌이 다르다).

## 4. 이 코드에 붙이는 방법

### 4.1 원칙

1. **화면만의 일이다.** 전부 `src/render3d/` 안에서 끝낸다. sim·락스텝·해시와 무관하다. 플레이어마다 따로 켜고 꺼도 된다.
2. **기다리지 않는다.** 지역 이동(`syncView` → `setMap`)은 지금처럼 동기로 곧장 세계를 만든다. 텍스처는 비동기로 받아 **다 받은 뒤 재질만 갈아 끼운다.** 로딩 때문에 한 프레임이라도 멈추면 4인 락스텝 입력이 밀린다.
3. **실패하면 지금 모습.** 파일이 없거나 GPU 가 형식을 못 읽으면 조용히 절차 생성 모습으로 남는다.
4. **충돌과 겉모습을 맞춘다.** sim 은 타일 단위로 막는다. 모델이 한 칸(1×1)을 넘으면 보이는 것과 막히는 곳이 어긋난다.
5. **배치는 그대로.** 어디에 무엇을 둘지는 지금의 타일 해시(`hash(tx, ty, salt)`)를 그대로 쓴다. 바뀌는 것은 지오메트리와 재질뿐이다.

### 4.3 텍스처 — 바닥·벽

**바닥** (`buildDark` 76~82행, `paintFloor`)
- 바닥 판은 반복 PBR 재질로 바꾼다. 텍스처 한 장이 2×2 타일을 덮게 한다.
- 반복 횟수는 `texture.repeat` 가 아니라 **지오메트리 UV 를 늘려서** 맞춘다. 텍스처는 여러 지역이 같이 쓰는데, 맵 크기는 지역마다 다르기 때문이다.
- 금·핏자국·이끼는 버리지 않는다. `paintFloor` 를 "무늬만 그리고 배경은 투명" 으로 바꾼 캔버스를 바닥 바로 위(y 0.003)에 얇은 판으로 한 장 더 깐다(`transparent`, `depthWrite: false`). 타일마다 밝기를 조금씩 다르게 칠하면 반복 무늬도 덜 보인다.
- 판석 격자선은 없어진다. 충돌은 벽 기준이라 바닥 격자와 무관하다.

**벽** (`buildDark` 120~131행)
- 지금은 1×1×1 상자를 높이 h(1.7~2.6)만큼 늘린다. 텍스처도 같이 늘어나 벽돌이 길쭉해진다.
- 상자 높이를 그 스타일의 평균 높이로 만들고 UV 의 v 도 그 높이만큼 늘린다. 인스턴스는 평균 대비 비율(±10% 안팎)만 늘린다. 이 정도는 눈에 안 띈다.
- 인스턴스 색(`setColorAt`)은 텍스처에 곱해진다. 지금 테마 색은 어둡다(예: 벽 `0x4e3430`). 그대로 곱하면 새까맣다 → `색조 = 테마 색을 밝기로 나눈 값을 흰색 쪽으로 60% 섞기` 같은 식으로 밝기 1 근처의 색만 곱한다. 값은 눈으로 맞춘다.

**재질 만들기 스케치** (시험 안 한 예시)

```ts
// src/render3d/realistic.ts (새 파일, 예시)
const mat = new THREE.MeshStandardMaterial({
  map: albedo,            // sRGB
  normalMap: normal,      // 선형
  roughnessMap: arm,      // arm 의 G 채널을 읽는다
  aoMap: arm,             // arm 의 R 채널 (r152+ 는 uv 채널 0 을 그대로 쓴다 — Texture.channel)
  metalness: 0,           // 돌·나무·흙은 금속이 아니다 → metalnessMap 은 안 쓴다
  roughness: 1,
})
for (const t of [albedo, normal, arm]) {
  t.wrapS = t.wrapT = THREE.RepeatWrapping
  t.anisotropy = 4        // 55° 로 내려다보는 바닥이 흐려지지 않게
}
```

### 4.4 재질 종류와 빛 비용

**Lambert 와 Standard**
- 지금은 전부 `MeshLambertMaterial` 이다. r185 의 Lambert 도 픽셀마다 빛을 계산하고, `normalMap`·`aoMap` 을 받는다(거칠기는 없다).
- 젖은 돌이 횃불에 번들거리는 "실사 느낌"은 거칠기(반사)에서 나온다 → 바닥·벽만 `MeshStandardMaterial` 로 바꾼다.
- 캐릭터·몬스터·작은 소품은 Lambert 그대로 둔다.
- 화면의 대부분은 바닥·벽이다. 그래서 비용 증가는 거의 이 둘에서 나온다. 품질 "가벼움"에서는 바닥·벽도 Lambert + normalMap 만 쓴다.

**빛 개수** — 지금 점광원(PointLight)
- 고정: 횃불 6(`world3d.ts` 349행) · 등불 4(`renderer3d.ts` 243행) · 출구마다 1 · 웨이포인트 · 타운 포털 · 금빛 상자 · 제단.
- 순간: 총 쏠 때마다 새로 하나(`spawnFlash`, 814행, 0.06초) · 폭발(634행) · 궁극기(1914행) · 스킬 장판(1976행).
- three 의 WebGL 렌더러는 **모든 픽셀에서 모든 점광원을 돈다**(거리로 잘라 주지 않는다). 빛 수 × 화면 픽셀이 비용이다. PBR 은 빛 하나당 계산이 Lambert 보다 무겁다.
- **빛 개수가 바뀌면 셰이더를 다시 고른다.** three 는 점광원 수를 셰이더 키에 넣는다(`WebGLLights` 의 `hash.pointLength` → `lights.state.version`). 처음 보는 개수면 그 자리에서 셰이더를 **새로 컴파일**한다 → 4인이 동시에 쏘면 "3개·7개·11개…" 가 처음 나올 때마다 멈칫한다. PBR 셰이더는 컴파일이 더 길다.
- 대책(실사 전에 먼저 하면 좋다):
  - 순간 빛은 **고정 풀**(예: 8개)을 만들어 두고 세기만 0↔값으로 바꾼다. `visible=false` 도 개수를 바꾸므로 쓰지 않는다. 등불도 같다(지금은 `visible` 을 끈다, 2145행 근처).
  - 지역에 들어갈 때 `renderer.compileAsync(scene, camera)` 로 미리 컴파일한다.
  - 판 도중 `renderer.info.programs.length` 가 늘지 않는지 잰다.

**환경** — 3.3 참고. `ColorEnvironment` 를 약하게, 또는 없음.

### 4.5 압축 — KTX2 / Basis

**왜**
- JPG/WebP 는 받을 때 작지만 GPU 에 올라가면 풀린다. 512² RGBA + 밉맵 = 약 1.33 MiB, 1K 는 약 5.3 MiB (한 장).
- KTX2 는 GPU 가 압축된 채로 쓴다(데스크톱은 BC 계열, 폰은 ETC/ASTC 로 변환). 메모리가 1/4~1/8 이다. 변환은 웹 워커에서 하므로 메인 스레드가 덜 멈춘다.
- 대신 변환기 0.58 MB(`basis_transcoder.wasm` 527 KB + `.js` 58 KB)를 한 번 받는다.

**만드는 도구** (전부 무료 · 오픈 소스, 사용자가 PC 에 설치)
- KTX-Software (Apache-2.0) — https://github.com/KhronosGroup/KTX-Software · 최신 v4.4.2 (2025-10-04, GitHub API 로 확인).
- glTF Transform CLI (MIT, npm 4.5.0) — `npm install --global @gltf-transform/cli`. KTX2 명령(`etc1s`·`uastc`·`optimize --texture-compress ktx2`)은 **KTX-Software 4.4.0 이상의 `ktx` 명령이 PATH 에 있어야** 돈다(소스 `toktx.ts` 로 확인).
- 이 둘은 프로젝트 의존성에 넣지 않는다. 결과 파일만 커밋한다(CI 는 그대로).

**명령 예** (KTX-Software v4.4.2 소스의 옵션 이름 기준. 처음 쓸 때 `ktx create --help` 로 한 번 확인)

```bash
# 색(albedo): ETC1S, sRGB, 512, 밉맵
ktx create --format R8G8B8_SRGB --encode basis-lz --qlevel 200 --generate-mipmap \
  --width 512 --height 512 --convert-texcoord-origin bottom-left \
  castle_brick_07_diff_1k.jpg albedo.ktx2

# 노멀: UASTC + zstd, 선형
ktx create --format R8G8B8_UNORM --assign-tf linear --encode uastc --zstd 18 --generate-mipmap \
  --width 512 --height 512 --convert-texcoord-origin bottom-left \
  castle_brick_07_nor_gl_1k.jpg normal.ktx2

# arm(AO·거칠기·금속): ETC1S, 선형 — 노멀과 같은 --format/--assign-tf 에 --encode basis-lz
```

**함정**
- **위아래 뒤집힘.** KTX2 는 `flipY` 를 하지 않는다. three 의 기본 도형(PlaneGeometry·BoxGeometry)은 UV 원점이 왼쪽 아래다. 그대로 쓰면 그림이 뒤집혀 붙고, **노멀맵의 초록(Y)이 반대가 되어 돌이 파여 보인다.** 그래서 위 명령에 `--convert-texcoord-origin bottom-left` 를 넣었다. glTF 모델 안의 텍스처는 glTF 규칙(왼쪽 위)이므로 이 옵션을 쓰지 않는다(glTF Transform 이 알아서 한다). 첫 시험 때 벽돌 줄눈의 그림자 방향을 눈으로 확인한다.
- **색공간.** 색만 sRGB, 노멀·arm 은 선형. KTX2Loader 는 파일에 적힌 전달 함수로 `colorSpace` 를 스스로 정한다(r185 `KTX2Loader.js` 로 확인). JPG 로 시범할 때는 `albedo.colorSpace = THREE.SRGBColorSpace` 를 직접 넣는다.
- **노멀 형식.** Poly Haven 은 `nor_gl`(OpenGL) 을 받는다. three 는 OpenGL 방식이다. `nor_dx` 를 받으면 초록이 반대다.

**불러오기 스케치** (시험 안 한 예시)

```ts
import { KTX2Loader } from 'three/examples/jsm/loaders/KTX2Loader.js'
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js'
import { MeshoptDecoder } from 'three/examples/jsm/libs/meshopt_decoder.module.js'

const ktx2 = new KTX2Loader()
  .setTranscoderPath(import.meta.env.BASE_URL + 'basis/')
  .detectSupport(renderer)                          // Renderer3D 의 this.gl
const gltf = new GLTFLoader().setKTX2Loader(ktx2).setMeshoptDecoder(MeshoptDecoder)
```

- **시범 단계는 KTX2 없이 JPG 로 한다.** `THREE.TextureLoader` 로 1K JPG 를 바로 쓴다(도구 필요 없음). 모습이 괜찮은지 먼저 보고, 크기·메모리를 잰 다음 KTX2 로 바꾼다. 이득이 작으면 512 WebP 로 멈춰도 된다.

### 4.6 모델 — GLB

- 형식은 GLB 하나로. 압축은 **meshopt** 를 쓴다. 해독기가 29 KB JS 라 Vite 가 묶어 준다. Draco 는 해독기(wasm 판 약 0.25 MB, JS 판 약 0.5 MB)를 따로 경로에 두어야 해서 쓰지 않는다.
- 줄이기 한 줄 (glTF Transform — `--compress` 기본값이 meshopt 다):

```bash
gltf-transform optimize Barrel_01_1k.gltf barrel.glb \
  --texture-compress ktx2 --texture-size 512 --simplify-ratio 0.5
# KTX-Software 가 없으면 --texture-compress webp (메모리 이득은 없다)
```

- 받은 모델은 부품이 여러 개일 수 있다. `optimize` 는 기본으로 장면을 펴고(`--flatten`) 합친다(`--join`). 결과가 **메시 하나·재질 하나**인지 `gltf-transform inspect` 로 확인한다.
- 게임에 넣는 곳은 지금 `inst()` 다. 지오메트리만 바꿔 넣는다.

```ts
// buildDark 234행 근처 (통) — 예시
const src = kit.barrel                         // 막 들어올 때 받아 둔 { geometry, material }
const geo = src.geometry.clone()
geo.computeBoundingBox()
const b = geo.boundingBox!
const s = 0.72 / (b.max.y - b.min.y)           // 지금 통 높이 0.72 에 맞춘다
geo.translate(-(b.min.x + b.max.x) / 2, -b.min.y, -(b.min.z + b.max.z) / 2).scale(s, s, s)
const barrel = inst(geo, src.material, crates.length * 2)   // 배치(put)는 지금 코드 그대로
```

- Poly Haven 모델은 실제 크기(미터)다. 게임은 1 = 타일 한 칸. **바운딩 박스로 지금 도형과 같은 크기로 맞춘다.** 한 칸을 넘지 않게.
- 종류마다 `InstancedMesh` 하나 → 그리기 호출은 종류 수만큼만 는다.
- 재질·텍스처는 막 캐시가 들고 있다. `World3D.dispose()` 에서 **공유 재질·텍스처를 지우지 않는다**(지역을 옮길 때마다 다시 올리게 된다). 막을 떠날 때만 지운다.

### 4.7 받는 때와 갈아 끼우기

- **막 단위.** 켠 사람이 그 막의 마을(또는 첫 지역)에 들어오면 그 막 파일을 뒤에서 받기 시작한다. 받는 동안은 지금 모습이다.
- **갈아 끼우기.** `buildDark` 가 만든 메시(바닥·벽·장애물)를 `World3D` 에 들고 있게 하고, `applyRealistic(kit)` 같은 함수 하나로 `mesh.material` 과 `geometry` 만 바꾼다. 받기가 끝났을 때 아직 같은 지역이면 바로 적용한다.
- **첫 프레임 멈칫 막기.** 갈아 끼운 뒤 `renderer.initTexture(t)` 와 `renderer.compileAsync(scene, camera)` 를 불러 GPU 업로드와 셰이더 컴파일을 미리 끝낸다.
- **GPU 에는 지금 지역 것만.** 한 지역은 재질 2~4개다. 막 캐시는 받은 데이터를 들고 있고, GPU 업로드는 지역마다 한다.

### 4.8 켜기/끄기

- `session.ts` `showMenu()` (792행)에 이미 "조작 안내 보기"·"소리 끄기" 토글이 있다. 같은 모양으로 **"실사 텍스처(실험) 켜기/끄기"** 를 더한다.
- 저장은 지금 관례대로 `localStorage` 키 하나(예: `brpg.gfx`). `try/catch` 로 감싼다(저장 못 해도 이번 판은 반영).
- 기본값은 **꺼짐**. 터치(폰)에서는 메뉴에 띄우지 않거나 꺼 둔다.
- 켜고 끌 때 게임을 다시 시작하지 않는다. 지금 지역의 재질만 바꾼다.

## 5. 성능 예산과 재는 법

### 5.1 예산

지금 배포본(`dist`)은 **전부 합쳐 1.1 MB** 다. 실사 파일은 이보다 훨씬 크므로 켠 사람만, 막 단위로 받는다.

| 항목 | 목표 | 근거 |
|---|---|---|
| 첫 화면 추가 다운로드 | **0 MB** | 기본 꺼짐 |
| 막 하나 (켰을 때) | **3~5 MB** | 재질 6~8개 × 0.15~0.35 MB(512 KTX2, 추정) + 모델 4~6개 × 0.1~0.3 MB |
| 4막 전체 (저장소의 게임용 파일) | **20 MB 이하** | GitHub 권장 저장소 1 GB 미만 · Pages 사이트 1 GB · 월 100 GB 전송(소프트) — 여유 있음 |
| basis 변환기 | 0.58 MB 한 번 | KTX2 를 쓸 때만 |
| GPU 텍스처 메모리 (지역 하나) | **32 MiB 이하** | 512 RGBA 재질 하나 약 4 MiB × 4 + 모델 / KTX2 면 1/4 |
| 그리기 호출 | 소품 **종류당 +1** | 인스턴스 |
| FPS | 끔 대비 **−10% 이내** | 아래 "재는 법" 의 같은 장면에서 |
| 지역 들어갈 때 멈칫 | 새로 생기지 않을 것 | 비동기 + 미리 컴파일 |

- 크기 수치 중 KTX2 결과 크기는 **추정**이다. 1K JPG 크기는 API 로 확인했다(예: `castle_brick_07` 1K = 색 0.66 + 노멀 1.00 + arm 0.27 = 약 1.9 MB). 512 KTX2 는 이보다 훨씬 작지만, 실제 값은 첫 변환 때 재서 이 표를 고친다.
- 한 파일이 100 MiB 를 넘으면 GitHub 가 막는다(50 MiB 부터 경고). 이 계획의 파일은 수백 KB 라 LFS 는 필요 없다.
- 2K·4K 는 받지 않는다. 카메라(거리 15.5, FOV 40)에서 타일 한 칸은 화면에서 약 64~128px 다. 512 텍스처가 2×2 칸을 덮으면 칸당 256 텍셀 — 이미 넉넉하다.

### 5.2 품질 단계

| 단계 | 내용 |
|---|---|
| 끔 (기본) | 지금 모습 그대로 |
| 실사 · 가벼움 | 512 텍스처 · 바닥·벽도 Lambert + normalMap · dpr 최대 1 · 해 그림자 1024 |
| 실사 · 좋음 | 512~1K · 바닥·벽 Standard · dpr 최대 2 (지금 `resize()` 와 같음) |

- 처음에는 "끔 / 켬" 둘만 둔다. 재 본 뒤 필요하면 셋으로 나눈다.
- dpr(화면 배율)은 비용을 크게 좌우한다. 지금 `resize()` 는 `Math.min(2, devicePixelRatio)` 다. 고해상도 노트북은 픽셀이 4배다.

### 5.3 재는 법

- **같은 장면**에서 끔/켬을 비교한다. 예: 같은 시드, 지하 묘지 1층 입구, 보통 난이도 봇 3명과 4인.
- 주소 뒤 `?stats=1` 이면 작은 계측 글자를 띄우게 한다(8장 1단계에서 만든다):
  - FPS 평균과 1% 최저 (`performance.now()` 로 프레임 시간을 모은다).
  - `renderer.info.render.calls` · `.triangles` (그리기 호출 · 삼각형).
  - `renderer.info.memory.textures` · `.geometries`.
  - `renderer.info.programs.length` (셰이더 수 — 판 도중 늘면 멈칫의 원인).
- 지역을 옮길 때 `setMap` 앞뒤와 첫 프레임까지 걸린 시간(ms)을 잰다.
- Chrome 개발자 도구 Performance 탭으로 긴 프레임을 찾는다.
- 사용자 PC(메인)와 가장 약한 노트북 둘에서 잰다. 결과는 HANDOVER 에 표로 남긴다.

## 6. 캐릭터는 왜 그대로 두나

**실사 캐릭터·몬스터는 범위 밖이다.** 이유:

- **사용자 확정 결정.** GUIDE 3장: "캐릭터는 배도라지 덕 캐릭터(오리)". 팬게임의 정체성이다.
- **구조가 다르다.** 오리는 뼈대 없이 도형으로 조립한다(`character3d.ts` — 달걀형 몸통 + 얼굴 텍스처). 실사 인물은 스킨 메시 + 뼈대 애니메이션이 필요하다. 새 파이프라인을 통째로 만들어야 한다.
- **몬스터 수.** 지금은 부품별 인스턴싱이라 100마리여도 종류당 6~8번 그린다. three 의 `InstancedMesh` 는 뼈대 애니메이션을 지원하지 않는다 → 스킨 몬스터는 한 마리마다 그리기 호출이 는다.
- **애니메이션 라이선스.** 무료 사람 애니메이션의 대표인 Mixamo 는 원본 파일 배포를 금한다(2장). 공개 저장소와 안 맞는다.
- **작아서 안 보인다.** 캐릭터는 화면에서 약 60~100px 이다. 실사 인물은 이 크기에서 뭉개지고, 어두운 실사 배경과 섞인다.

**추천 조합: 실사 배경 + 양식화 캐릭터.**
- 밝고 단순한 오리 실루엣이 어둡고 거친 돌바닥 위에서 **더 잘 보인다.** 쿼터뷰 슈터는 "내가 어디 있나" 가 가장 중요하다.
- 배경은 움직이지 않고 인스턴스로 그린다. 실사 비용을 가장 싸게 낼 수 있는 곳이다.
- 실사화의 위험(성능·버그)이 배경에만 갇힌다. 끄면 원래대로다.
- 나중에 원하면 몬스터 부품에 노멀맵 정도만 입혀 본다(별도 결정).

## 9. 하지 말 것 (함정 모음)

- 텍스처를 받느라 지역 이동을 기다리게 하지 않는다(락스텝 입력이 밀린다).
- 새 `PointLight` 를 그때그때 만들지 않는다. 빛 개수가 바뀌면 셰이더를 다시 고르고, 처음이면 컴파일한다.
- KTX2 를 기본 도형에 쓸 때 위아래를 맞춘다(`--convert-texcoord-origin bottom-left`). 안 그러면 노멀이 뒤집힌다.
- 노멀·arm 텍스처를 sRGB 로 두지 않는다.
- 어두운 테마 색을 PBR 텍스처에 그대로 곱하지 않는다.
- 벽 높이만큼 늘린 상자에 텍스처를 그대로 붙이지 않는다(벽돌이 늘어난다).
- 모델을 한 칸보다 크게 두지 않는다(충돌과 어긋난다).
- 받은 원본(zip·1K·2K·4K)을 저장소에 올리지 않는다. `art-src/` 는 `.gitignore`.
- 2K 이상을 게임 파일로 쓰지 않는다.
- 공유 재질을 지역마다 `dispose()` 하지 않는다.
- 라이선스가 모델마다 다른 곳(Sketchfab·OpenGameArt)은 "무료" 표시만 믿지 않는다. 페이지의 라이선스 이름을 확인하고 저장한다.
- Fab·Megascans·Textures.com·ShareTextures·Mixamo 파일을 저장소에 넣지 않는다.
- 폰에서 자동으로 켜지 않는다.
