## 1. 목표와 제약

### 절대 제약 (배도라지 덕과 같다)

1. **서버를 두지 않는다.** 정적 파일만 배포하고, 멀티는 브라우저끼리 직접 붙는다.
2. **무료.** 카드 등록이 필요한 서비스는 제안도 하지 않는다. TURN 은 쓰지 않는다(덕 PREP C · DESIGN 15장).
3. **최대 4인.** 풀 메시 연결 수(4인 = 6쌍)와 락스텝 지터 전파 때문이다(덕 DESIGN 8.-1). 늘리지 않는다.
4. **비상업 팬 프로젝트.** 패러디 명칭, 외부 에셋 없이 모델은 코드로 조립하고 소리는 절차 생성한다(저작권 문제 없음).
5. 계정이 없으니 **세이브는 각자의 브라우저**에 있다. 치트 방지는 불가능하다(친구끼리 하는 게임).

### 목표

- 디아블로의 재미 세 가지를 옮긴다: **무리를 쓸어 담는 전투 · 전리품 · 성장.**
- 슈터의 손맛은 남긴다: 직접 겨눠 쏘기, 구르기 무적, **정확히 겨눈 탄이 치명타**(확률 추첨이 아니다).
- 혼자 해도 재미있고, 친구 2~4명이면 역할(탱커·딜러·치유)이 생긴다.

### 목표가 아닌 것

지속되는 온라인 세계 · 거래소 · 순위표 · 게임 안 PvP(배도라지 덕으로 연결한다) · 5인 이상 · 서버 저장. (12장)

## 2. 게임 흐름

```
로비(방 목록) ─ 방 만들기/들어가기/혼자 하기
   └ 대기실 = 마을 : 캐릭터 고르기 · 장비 정리 · 보관함 · 상점 · 원정(지역·난이도) 선택 · 준비
        └ 원정 : 1층 → 2층 → … → 보스 층   (층마다 시드로 생성, 계단으로 전원 같이 이동)
             └ 결과 : 얻은 경험치·아이템 요약 → 대기실로 (다시 가기)
```

**왜 "원정" 단위인가.** 서버가 없으면 세계를 계속 켜 둘 곳이 없고, **방장의 연결이 곧 방**이다(덕 DESIGN 8.3).
20~30분에 끝나는 단위로 끊으면 방장이 끊겨도 잃는 것이 작고, 성장(레벨·아이템)은 각자 세이브에 이미 남아 있다. 디아블로 3 의 균열과 같은 구조다.

## 4. 핵심 기술 결정

### 4.1 넷코드는 결정론 락스텝을 그대로 쓴다

협동 RPG 는 화면에 몬스터가 수십~수백이다. 방식별 비교:

| | **락스텝 (권장)** | 방장 권위 + 상태 전송 |
|---|---|---|
| 통신량 | **몬스터 수와 무관.** 한 사람이 보내는 양 ≈ 15KB/s (입력 10바이트 × 8틱 중복 × 60Hz × 3명) | 활성 몬스터 150 × 10바이트 × 15Hz ≈ 22KB/s **× 손님 수** — 방장 업로드 67KB/s, 핫스팟에서 위태롭다 |
| 기존 코드 | sim·락스텝·리싱크·난입 **전부 재사용** | 손님 쪽 예측·보간을 새로 짠다. 결정론 자산을 버린다 |
| 약점 | 가장 느린 사람에게 모두가 맞춰진다(스톨) · 입력 지연 2~6틱 | 방장만 쾌적, 손님은 몬스터가 순간이동 |
| PvE 에서 | 입력 지연은 PvP 보다 훨씬 덜 거슬린다. 지연 상한을 8틱까지 늘려 스톨을 줄일 수 있다 | — |

스타크래프트·에이지 오브 엠파이어 같은 RTS 가 유닛 수백을 이 방식으로 돌린다(입력만 보내고 각자 계산). **덕에서 이미 검증된 것을 쓰는 게 가장 큰 이점**이다.

### 4.2 몬스터의 기억은 전부 `GameState` 안에 둔다

덕의 봇은 기억(`BotMemory`)이 상태 밖에 있어서, 리싱크로 판을 되돌리면 봇이 피어마다 다른 결정을 내렸다 — 그래서 방장이 봇 입력을 대신 보냈다(덕 DESIGN 8.6).
몬스터 수백 마리의 입력을 보낼 수는 없으므로, **표적·쿨다운·상태 기계·경로 캐시까지 전부 상태에 넣어** 스냅샷만 받으면 누구나 같은 결과를 내게 한다.
난수도 `state.rng` 하나만 쓴다. 이것이 이 프로젝트의 **결정론 규칙 1번**이다.

### 4.3 입력 확장: 버튼 16비트 + 명령 한 개

덕의 규칙 "플레이어의 의사는 반드시 `Input` 에 실어 보낸다" 를 그대로 지킨다. 인벤토리 조작도 예외가 아니다.

```
Input (10바이트) = mx, my, aim(2), aimDist, buttons(2), cmd, arg(2)
buttons: 사격 · 보조(우클릭) · 재장전 · 구르기 · 달리기 · 스킬Q · 스킬E · 고유기R · 물약 · 상호작용F
cmd    : 없음 | 줍기(바닥 아이템 id) | 장착(칸) | 해제(칸) | 버리기(칸) | 칸 바꾸기 | 스킬 포인트(스킬) | 계단 투표 …
```

한 틱에 명령 하나(초당 60개)면 충분하다. 최근 8틱 중복 전송에 같이 실리므로 패킷이 유실돼도 명령이 사라지지 않는다.
**UI 는 상태를 직접 바꾸지 않고 명령만 넣는다** — 인벤토리 창은 `state.players[me]` 를 읽어 그리기만 한다.

### 4.4 한 번에 한 맵, 전원 같이 이동

sim 하나가 맵 하나만 돈다. 누군가 계단에서 상호작용하면 10초 카운트다운 뒤 **전원이 다음 층으로** 간다(살아 있는 사람이 있으면 쓰러진 사람도 같이 일어나 이동).
파티가 층을 나눠 다니게 하려면 맵 여러 장을 동시에 돌려야 하고 상태·성능·난입이 전부 복잡해진다 — 하지 않는다.
**마을은 대기실 UI 다**(5.7). 원정 중 마을 왕복(타운 포털)은 없다.

### 4.5 세이브: 캐릭터 = 직업 = 세이브 칸

- 12명 각자 레벨·스킬·장비·가방을 가진다. 골드와 **보관함은 12명이 공유**한다. 캐릭터 생성 화면이 필요 없다 — 로비 캐릭터 목록에 레벨만 덧붙는다.
- 저장소는 `localStorage`(키 접두사로 덕과 분리 — 같은 `goormigrm.github.io` 출처다). 세이브에 **버전 번호**를 넣고 올릴 때마다 변환 함수를 둔다.
  쓰기 전에 직전 세이브를 한 벌 보관하고 체크섬으로 깨짐을 가린다(치트 방지가 아니라 **사고 방지**).
- **내보내기/가져오기**: 세이브를 `.json` 파일로 내려받고 올린다. 메인 PC ↔ 노트북 이동과 백업의 유일한 수단이다.
- **원정 중에는 sim 상태가 정본이다.** 세션이 30초마다 · 층을 넘을 때 · 나갈 때 `state.players[me]` 에서 내 캐릭터를 뽑아 저장한다.
- **멀티**: 시작(`start`)·난입(`joinLive`) 메시지에 각자의 **캐릭터 시트**(레벨·스킬·장비·가방 ≈ 3KB)를 실어 모두가 같은 틱에 상태에 넣는다.
  받은 시트는 범위만 본다(레벨 상한 · 옵션 값이 아이템 레벨 범위 안) — 깨진 데이터로 판이 어긋나지 않게 하는 용도다.

### 4.6 전리품은 개인별

몬스터가 아이템을 떨어뜨릴 때 **그 자리에 있는 사람 수만큼 각자 몫을 굴린다.** 상태에는 전부 있고, 화면에는 자기 것만 보인다(주인 표시).
먼저 줍기 싸움이 없고, 자기 무기군 위주로 떨어지게 기울일 수 있다(무기 7종 × 4인이라 공용이면 대부분 남의 것이다).
**가방에서 버린 아이템은 모두에게 보인다** = 친구에게 주는 방법.

### 4.7 방장이 끊기면: 혼자 이어하기

락스텝은 **모두가 판 전체를 갖고 있다.** 방장이 끊기면 남은 사람은 각자 그 상태에서 다른 자리를 비우고(`dropPlayer`) **오프라인으로 원정을 마칠 수 있다.**
남은 사람끼리 방을 이어가는 것(방장 넘기기)은 풀 메시가 이미 뚫려 있어 가능성은 있지만, 덕에서도 하지 않은 일이라 M8 의 도전 과제로 둔다.

### 4.8 상태가 커진다 — 덕 코드에서 고쳐야 하는 세 곳

| 지금 (덕) | 문제 | 바꿀 것 |
|---|---|---|
| 매 틱 `snapshot()` = `structuredClone(전체)` (보간용 `prev`) | 몬스터 수백이면 틱마다 0.5ms+ 와 GC | 보간용은 **위치·각도 배열만** 복사. 전체 복사는 리싱크·난입 때만 |
| `hashState` = `JSON.stringify(전체)` 후 FNV | 60틱마다 100KB+ 문자열 | 숫자 필드를 직접 도는 **롤링 해시**. 영역별(플레이어/몬스터/아이템) 해시를 따로 내 어긋난 곳을 바로 안다 |
| 리싱크·난입이 상태 전체를 JSON 으로 전송 | 추정 150~200KB | **잠든 무리는 펼치지 않는다** — 상태에는 `{종류, 수, 자리, 시드}` 만 두고 플레이어가 다가오면 개체로 펼친다. 크기는 M2 에서 실측 |

## 5. 게임 시스템

### 5.1 캐릭터와 스킬

- 기본 공격 = 지금 무기 그대로(연사·재장전·반동 유지, **예비 탄은 무한**). 패시브도 유지하되 PvE 값으로 조정한다.
- **무기군 스킬 2개(Q·E) + 캐릭터 고유기 1개(R)** = 7무기군 × 2 + 12 = **26개.** 같은 무기를 쓰는 캐릭터는 Q·E 를 공유하고 패시브와 고유기로 갈린다.
- 스킬은 **재사용 대기시간**만 쓴다(마나 없음). 자원은 덕의 **기력** 하나 — 구르기·달리기·막기.
- 레벨 2·5·10 에 Q·E·R 이 열리고, 레벨마다 스킬 포인트 1 로 단계를 올린다(단계당 피해·범위·쿨 개선, 최대 5).

| 무기군 | 캐릭터 | 역할 | Q / E (예시 — 확정 아님) |
|---|---|---|---|
| 기관총 | 철면덕 | 탱커 | 제압 사격(전방 둔화) / 버티기(피해 감소 + 도발) |
| 소총 | 침착덕 · 기열덕 · 우재덕 | 원거리 딜 | 관통탄 / 수류탄 |
| 산탄총 | 매직덕 · 풍월덕 | 근거리 · 치유 | 밀쳐내기 / 화염탄 |
| 후라이팬 | 승빠덕 | 근접 · 방어 | 회전 휘두르기 / 돌진 강타(기절) |
| 권총 | 단군덕 · 우원덕 | 정찰 · 기동 | 연막(표적 해제) / 난사 |
| 저격총 | 옥냥덕 · 통천덕 | 보스 딜 | 표식(받는 피해 ↑) / 일직선 관통 |
| SMG | 주펄덕 | 돌격 | 질주 사격 / 섬광탄 |

고유기는 지금 패시브의 확장으로 짓는다(예: 매직덕 "진료" → 주변 아군 치유, 단군덕 "중계" → 층 전체 몬스터 위치 표시).
**1차는 6명 — 무기가 전부 다른 조합**(10장 결정 4): 철면덕(기관총·탱커) · 침착덕(소총·원거리) · 단군덕(권총·정찰) · 매직덕(산탄총·치유) · 승빠덕(후라이팬·근접) · 옥냥덕(저격총·보스 딜). SMG(주펄덕)와 나머지 5명은 M7.

### 5.2 전투 규칙 — 슈터에서 달라지는 것

- **아군 오사 없음.** 탄은 아군을 지나간다.
- **치명타 = 약점 사격.** 덕의 헤드샷 규칙 그대로: 쏘는 순간 커서가 그 몬스터 위에 있고 그 탄이 그 몬스터를 맞히면 치명타. 아이템은 **치명타 확률이 아니라 배율**을 올린다.
  무리 속에서는 너무 쉽게 터질 수 있다 — M1 에서 손으로 확인하고, 밋밋하면 "엘리트·보스에게만 약점" 으로 좁힌다.
- **구르기 무적은 그대로.** 몬스터 투사체와 보스 장판은 느리고 예고가 있어 **구르기로 피하는 게임**이 된다.
- 몬스터는 밀려난다(넉백) · 느려진다 · 기절한다 — 세 가지 상태 이상만 둔다.
- 시야 제한(전장의 안개)은 **유지**한다. 던전 분위기에 맞고, 아군 시야 공유는 이미 구현돼 있다.

### 5.3 몬스터

- **원형 6종**(1차): 떼(돌진) · 사수(느린 투사체) · 자폭 · 방패(앞 피해 감소 — 뒤를 치게 해 협동을 만든다) · 소환사 · 돌격수(예고 뒤 직선 돌진). 지역마다 겉모습과 수치만 바꿔 12종+.
- **엘리트**: 보통 몬스터 + 접두 능력 1~2개(빠름 · 단단함 · 분열 · 폭발 · 보호막 · 흡혈). 졸개를 데리고 다닌다. 좋은 전리품의 주 공급원.
- **보스**: 지역당 1. 패턴 3~4개를 체력 구간별로 돌린다(바닥 예고 → 피함). 체력 바는 화면 위.
- **AI 는 싸게**: 길찾기는 몬스터마다 BFS 하지 않고 **플레이어별 흐름장(flow field)** 을 15틱마다 번갈아 갱신해 따라간다. 사수의 시선 확인은 덕의 `rayCast` 재사용.
  서로 겹침은 공간 해시로 이웃만 본다. **플레이어 25칸 밖 무리는 잠든다**(4.8).
- 겉모습은 캐릭터처럼 **프리미티브 조립**, 종류별 `InstancedMesh` 로 한 번에 그린다. 뼈대 애니메이션 없이 통통 튐·기울임·찌그러짐으로 표현한다.

### 5.4 던전

- 지역 3개 = 덕의 생성기 3종: **지하 스튜디오**(방·복도) · **마당/숲**(트인 지형) · **지하 주차장**(기둥 격자). 덕의 통행 보정(갇힘 없음 · 우회도 1.5 이하)을 그대로 쓴다.
- 층 크기 96×96 ~ 128×128칸(덕 4인 맵은 80×60). 방마다 **무리 묶음**을 시드로 배치하고, 계단은 입구에서 가장 먼 쪽.
- 층 요소: 상자(전리품) · 항아리류(부서짐 — 덕의 모래주머니 코드 재사용) · 회복 샘 · 함정 약간 · **탐험 지도**(Tab, 밝힌 곳만).
- 원정 = 층 4~6 + 보스 층. 층이 깊을수록 몬스터·아이템 레벨이 오른다.

### 5.5 아이템

- **장비 5칸**: 무기(자기 무기군만) · 머리 · 몸 · 장신구 ×2. **가방 30칸**(한 칸 = 한 개, 테트리스 없음) · 공유 보관함 60칸.
- **등급**: 일반(옵션 0) · 마법(1~2) · 희귀(3~4) · **전설**(고유 효과 1 + 옵션 2~3). 세트는 없다.
- **옵션 약 20종**: 피해 · 연사 · 재장전 · 탄창 · 치명타 배율 · 체력 · 피해 감소 · 이동 속도 · 기력 · 구르기 · 처치 시 회복 · 스킬 쿨 · 골드·경험치 획득 등.
- 표현은 작게: `{기반, 등급, 아이템 레벨, [옵션 id, 값]×≤6}` ≈ 80바이트. 생성은 sim 의 `state.rng` 로만(모든 브라우저가 같은 아이템).
- 물약: 회복 물약 하나(충전식, 처치로 충전). 소모품 가방 관리는 두지 않는다.
- 외형: 무기는 등급 색 빛, 방어구는 **보이지 않는다**(얼굴·머리 캐리커처가 캐릭터의 정체성이라 가리지 않는다).

### 5.6 성장

- 레벨 상한 **30**(콘텐츠와 함께 올림). 레벨업: 체력·피해 소폭 자동 성장 + 스킬 포인트 1. **능력치 직접 분배는 없다** — 빌드는 아이템과 스킬로 만든다.
- 난이도 3단계(보통 → 어려움 → 지옥, 가칭). 윗단계는 앞 단계 보스를 잡아야 열린다. 단계가 오르면 몬스터 수치·아이템 레벨·전설 확률이 오른다.
- 끝 콘텐츠는 "더 높은 난이도에서 더 좋은 옵션" 의 반복으로 충분하다(친구용 게임).

### 5.7 마을 = 대기실

걸어 다니는 3D 마을을 만들지 않고 **대기실 화면에 탭**을 단다: 장비·가방 / 보관함 / 상점(사기·팔기·도박성 미확인 아이템) / 원정 선택.
원정 밖에서는 sim 이 없으므로 시트를 **로컬에서 직접** 고친다 — 단, 아이템·장착 계산은 `core/` 의 같은 순수 함수를 쓴다(원정 중 명령 처리와 한 코드).
혼자 하기도 같은 화면을 거친다.

### 5.8 쓰러짐과 부활

- 체력 0 = **쓰러짐.** 동료가 곁에서 상호작용 3초면 일어난다(체력 40%). 혼자이거나 아무도 안 오면 12초 뒤 층 입구에서 일어난다.
- **전원이 쓰러지면** 층 입구에서 다시 시작하고 엘리트·보스 체력이 돌아온다. 무엇을 잃는지는 방장이 고른 **죽음 규칙**(10장 7: 없음 · 소실 · 하드코어)을 따른다.

### 5.9 인원 보정

몬스터 체력 × (1 + 0.6 × (인원−1)), 무리 크기 소폭 증가, 전리품은 개인별이라 그대로. 난입·이탈 시 **다음에 깨어나는 무리부터** 적용한다(이미 싸우는 몬스터는 안 바꾼다 — 결정론이 단순해진다).

- 소리: 덕의 절차 생성 효과음 + 줍기(등급별 음)·레벨업·스킬·몬스터. **전설 아이템이 떨어지는 소리**는 따로 공들인다. 배경음 3곡(마을·던전·보스).

**M2 를 앞에 두는 이유**: "락스텝 + 몬스터 수백" 이 이 계획에서 가장 큰 불확실성이다. 콘텐츠를 쌓기 전에, 몬스터 3종만 있는 상태에서 4인 결정론·성능·전송 크기를 먼저 확인한다.
여기서 안 되면 4.1 의 표 오른쪽(방장 권위)으로 갈아타는데, 그 비용이 가장 싼 시점이 M2 다.
