## 0. 결론 (먼저 읽기)

- **실사에 가까운 무료 괴물은 거의 전부 Sketchfab 의 CC-BY 다.** 출처 표기만 하면 공개 저장소·웹에 올려도 된다.
- **움직이는 CC0 실사 괴물은 없다.** Sketchfab 에서 "CC0 + 애니메이션 + 내려받기" 로 찾으면 박물관 소장품·곤충·물고기만 나온다.
- CC0 실사는 **정지 스캔**뿐이다. ffish.asia 의 진짜 거미 사진측량(CC0)이 쓸 만하다. 뼈대가 없어 우리가 줄이고 뼈를 넣어야 한다.
- Quaternius · KayKit 은 CC0 이고 움직이지만 **양식화(로우폴리)** 다. 실사가 없는 종류의 예비로만 둔다.
- **Sketchfab 은 무료 계정으로 로그인해야 받을 수 있다.** 받기 API 가 로그인 없이는 401 을 돌려준다(확인). → **사용자가 직접 받아야 한다.**

**종류별 상태**

| 상태 | 종류 |
|---|---|
| 좋은 실사 후보 있음 (실사 3.5~4 · 움직임 있음) | 구울 · 해골 궁수 · 굶주린 늑대 · 독거미 · 거미 여왕(보스) · 방패병 · 도살자(보스) |
| 쓸 만함 (실사지만 클립 1개, 또는 다른 모델로 대신) | 부푼 시체(구울 모델의 "살찐 몸" 모양 키) · 강령술사(두건 교도·검은 마법사) · 관리인(검은 거인 기사) · 그림자(두건 쓴 망령) · 보물 고블린(창백한 소형 괴물) |
| 약함 (맞는 실사가 없다 — 대용 + 코드 부품) | 버섯 주술사(숲 마녀 + 코드 버섯 갓) · 산성 토사꾼(기어다니는 변이 인간) · 포격 악마(돼지 악마·괴수 악마 + 코드 포신) · 심연의 군주(괴수 악마, 뼈대만 있고 클립 없음) |

- **첫 묶음 추천 (사용자 승인 뒤 받기):** 구울 · 해골 궁수 · 늑대 · 독거미 · **거미 여왕(보스)** 다섯 + CC0 사람형 애니메이션 모음 하나(3장).
  - Sketchfab 원본 합계 **약 84 MB**. 원본은 `art-src/`(로컬, 저장소에 안 올림)에만 둔다.
  - 줄인 뒤 게임 파일은 **합계 3~4 MB** 목표.
  - 가장 흔한 몬스터(구울은 4막 모두)와 2막 무리(늑대·거미)를 먼저 덮는다. 보스는 클립이 11개라 애니메이션 연결을 시험하기 좋은 여왕으로.
- **사람형 후보는 대부분 클립이 1개(대기나 걷기)다.** 공격·죽음은 **Quaternius "Universal Animation Library"(CC0)** 에서 옮겨 붙인다(리타깃).
- **화풍 통일 안:** 한 작가(DJMaesen, `@bumstrum`)가 좀비·구울·해골 기사·소형 괴물·판금 기사·교도·거인 기사·괴물을 **같은 화풍(어두운 반실사, 2K PBR)** 으로 CC-BY 로 올려 두었다. 8종을 이 작가로 맞추면 화면이 통일된다. 대신 클립이 1개씩이라 리타깃이 꼭 필요하다.
- **그리는 방식:** 무리와 시체는 **애니메이션을 모프 프레임으로 구워 `InstancedMesh.setMorphAt`** 으로(종류당 그리기 호출 1~2), 보스와 가장 가까운 몇 마리는 `SkinnedMesh + AnimationMixer`. 받기 실패·"끔"·폰은 **지금 절차 모델 그대로.** (1.4)

## 1. 지금 괴물 그리기와 제약 (코드 기준)

### 1.1 지금 방식 — `src/render3d/monsters3d.ts`

- 종류마다 부품(몸통·머리·턱·눈·팔·다리·무기)을 `InstancedMesh` 하나씩 둔다. 부품당 최대 220(`CAP`).
- 매 프레임 몬스터마다 "뿌리 행렬 × 부품 행렬" 을 채운다. 100마리여도 **종류당 그리기 호출 = 부품 수(4~11)**.
- 뼈대가 없다. `Anim` 값으로 움직인다.
  - `walk` 걸음 위상 · `move` 이동 정도 · `wind` 예고 0→1 · `swing` 휘두름 1→0 · `flash` 맞음 · `dead` 넘어짐 · `squash` 스프링 · `yaw` 방향.
- 크기 = `def.r / 13` (구울 13px 기준). 정예 1.35배, 우두머리 1.7배.
- 색은 `instanceColor` 로 곱한다: 맞음 번쩍(빨강 · 치명타 금색), 예고 중 붉게 달아오름, 정예 금빛 맥동.
- 눈은 `MeshBasicMaterial` — 조명과 상관없이 어둠에서 빛난다(이 게임 괴물의 정체성).
- 시체: 최대 90구, 24초. 뒤로 넘어졌다가 끝 1.5초에 가라앉는다. 살아 있는 몬스터와 같은 부품 메시로 그린다.
- 체력 바 높이는 `MONSTER_TOP`. 재질은 전부 Lambert.

### 1.2 수와 분포 — `src/core/world.ts` · `src/core/monsters.ts`

- 지역당 몬스터: 1막 130 · 2막 100 · 3막 78 · 4막 85 (world.ts 주석). 무리는 3~10마리. 화면에는 수십 마리 + 시체.
- **구울은 4막 모두에 나온다(가장 많다).** 해골 궁수 1·3막 · 부푼 시체 1·2·3막 · 늑대·독거미·버섯 주술사 2막 · 방패병·산성 토사꾼·강령술사 3·4막 · 그림자·포격 악마 4막. 보물 고블린은 어디서나.
- 보스는 막마다 하나: 도살자(1) · 거미 여왕(2) · 관리인(3) · 심연의 군주(4).
- 부르는 몬스터가 있다: 강령술사→구울, 관리인→방패병, 여왕→새끼 거미, 군주→그림자. 둘이 같은 때 준비돼 있어야 한다.

### 1.3 GLB(뼈대 모델)로 바꿀 때의 제약

- three 의 `InstancedMesh` 는 **스키닝을 하지 못한다.** 뼈대 모델을 몬스터마다 `SkinnedMesh` 로 두면 그리기 호출 = 마리 수 × 재질 수. 그림자를 켜면 두 배.
  - 예: 60마리 × 재질 2 = 120 호출 + 그림자. 데스크톱은 버틸 수 있지만 폰·약한 노트북은 힘들다(추정 — 재 봐야 한다).
  - 뼈 계산(CPU)과 `AnimationMixer` 도 마리마다 돈다.
- 시체 90구를 스킨 메시로 두면 더 무겁다. **시체는 정지 포즈면 충분하다.**
- **예고 틱이 종류마다 다르다(10~48틱).** 공격 클립을 고정 속도로 틀면 보이는 휘두름과 판정 시각이 어긋난다. 클립 시간을 `wind` 값으로 직접 맞춰야(스크럽) 한다. 손맛과 공정성의 핵심이다.
- 화면만의 일이다. sim · 락스텝 · 해시와 무관하다. 받기가 늦어도 판은 기다리지 않는다.

### 1.4 권장 통합 방식

**세 가지 그리는 법을 종류마다 고른다.**

| 방식 | 쓰는 곳 | 그리기 호출 | 장단 |
|---|---|---|---|
| A. `SkinnedMesh` + `AnimationMixer` (마리마다 `SkeletonUtils.clone`) | 보스 · 가장 가까운 N마리(예: 8) | 마리 × 재질 | 클립 섞기가 부드럽다. 비싸다 |
| B. **구운 모프 인스턴스** — 클립을 프레임 몇 장(모프 타깃)으로 구워 두고, 마리마다 `InstancedMesh.setMorphAt` 으로 프레임을 고른다 | 무리 전체 · 시체(죽음 마지막 프레임 고정) | 종류당 1~2 | 수백 마리도 된다. 프레임 사이는 두 장을 섞는다. 굽는 도구가 필요 |
| C. 지금 절차 부품 | 받기 전 · 받기 실패 · "끔" · 폰 | 지금과 같음 | 대체용. 지우지 않는다 |

**B 가 핵심이다.**
- three r185 `InstancedMesh` 에 `setMorphAt` · `morphTexture` 가 있다(`node_modules/three/src/objects/InstancedMesh.js` 355행 — 확인).
- three 예제 `webgl_instancing_morph` 가 같은 방식이다 (확인 못 함 — 예제 파일이 이 저장소에 없다).
- 굽기: `tools/` 에 스크립트 하나. GLB 를 읽어 클립마다 프레임을 뽑아 모프 타깃으로 저장한 새 GLB 를 만든다.
  - `SkinnedMesh.getVertexPosition()`(뼈 변형 포함)이 r185 에 있다(확인). Node 에서 돌고 WebGL 이 필요 없다. 노멀은 프레임마다 다시 계산.
  - 프레임 예산: 대기 4 · 걷기 8 · 공격 6(예고 3 + 휘두름 3) · 맞음 2 · 죽음 6 ≈ **26장**.
  - 정점 5천 × 26장 × (위치 + 노멀) ≈ 종류당 GPU 약 4 MiB. 60마리의 프레임 값 갱신은 CPU 로 가볍다.

**`Anim` → 클립 대응**
- `move` · `walk` → 걷기 프레임. 걸음 위상은 지금처럼 `def.speed` 로 쌓는다(발이 미끄러지지 않게).
- `wind` 0→1 → 공격 **예고** 프레임을 값으로 직접 고른다. 틱과 정확히 맞는다.
- `swing` 1→0 → **휘두름** 프레임.
- `dead` → 죽음 클립, 끝나면 마지막 프레임 고정. 가라앉기는 지금 코드 그대로.
- `squash`(맞으면 움찔)는 뿌리 스케일 스프링 그대로 둔다. 손맛이다.

**색 · 빛 유지**
- 번쩍임 · 예고 붉음 · 정예 금빛은 지금처럼 `instanceColor` 로 곱한다. Standard 재질도 받는다. 1 보다 큰 값으로 밝힌다.
- **빛나는 눈은 남긴다.** 모델 머리 위치(종류별 오프셋)에 지금의 눈 부품만 겹쳐 그린다.
- GLB 는 `MeshStandardMaterial` 로 온다. 어두운 장면에서 너무 어두우면 `emissive` 를 조금 주거나, "가벼움" 단계에서 Lambert + normalMap 으로 바꾼다.
- 그림자: 보스만 `castShadow`. 무리는 끄거나 둥근 그림자 판. 계측으로 정한다.

**크기 · 방향**
- 바운딩 박스로 발을 y=0, 정면을 +z, 키를 지금 높이(`MONSTER_TOP` 에서 머리 위 여유를 뺀 값)에 맞춘다. 몸 반지름 `r` 과 어긋나지 않게.
- Sketchfab 모델은 단위·축이 제각각이다. 종류마다 한 번 맞춰 표로 둔다.

**예산**

| 항목 | 목표 |
|---|---|
| 텍스처 (색 · 노멀 · ORM 3장) | 일반 **512²** · 보스 **1024²**. 4K 원본은 전부 줄인다. 나중에 KTX2 (배경 문서 4.5) |
| 삼각형 | 일반 **5천~8천** · 보스 **2만~3만** 이하 |
| GLB 한 개 (meshopt + WebP/KTX2) | 일반 **0.3~0.6 MB** · 보스 **1~2 MB** |
| 막 하나 (보스 1 + 일반 3~5) | **3~5 MB** |
| 그리기 호출 | 무리 종류당 1~2 (+ 눈 1) · 보스 재질 수만큼 |

**받는 때 (막 단위, 배경 문서 4.7 과 같은 방식)**
- 공통: 구울 · 보물 고블린 — 첫 던전에 들어갈 때.
- 1막: 해골 궁수 · 부푼 시체 · 도살자.
- 2막: 늑대 · 독거미 · 버섯 주술사 · 거미 여왕.
- 3막: 방패병 · 강령술사 · 산성 토사꾼 · 관리인.
- 4막: 그림자 · 포격 악마 · 심연의 군주.
- 받는 동안과 실패하면 C(절차 모델). 받기가 끝나면 그 종류만 갈아 끼운다.

**켜기/끄기**
- ESC 메뉴 "실사 괴물(실험)". 기본 **끔**. 폰에서는 숨긴다. 배경 실사 토글과 따로 둔다.

**단계 (한 단계 = 한 커밋, 재고 되돌릴 수 있게)**
1. 보스 1종(거미 여왕)을 A 로. 1마리라 비용 걱정이 없다. 모습 · 밝기 · 크기 확인.
2. 구울을 A 로, 가장 가까운 8마리만. 나머지는 C. `?stats=1` 로 잰다.
3. 구울을 B 로 굽는다 → 무리 전체 + 시체.
4. 나머지 종류를 막 순서로.

**변환 도구** (사용자 PC 에 설치 · 저장소 의존성에 넣지 않음)
- glTF Transform CLI: `gltf-transform inspect` 로 클립 · 뼈 이름 확인, `optimize --texture-size 512 --compress meshopt` 로 줄이기.
- Blender: 면 줄이기 · 클립 나누기 · 리타깃. 스킨 메시에 `gltf-transform --simplify` 가 안전한지는 (확인 못 함) → 줄이기는 Blender 가 안전하다.
- 클립 하나에 여러 동작이 이어 붙은 모델(Sketchfab 에 많다)은 `THREE.AnimationUtils.subclip` 으로 프레임 구간을 잘라 쓴다(r185 에 있음 — 확인). 구간은 받은 뒤 확인.
- 리타깃은 `SkeletonUtils.retargetClip`(r185 에 있음 — 확인) 또는 Blender 에서 미리.

  - Sketchfab 라이선스 목록 API(`/v3/licenses`)로 CC BY 가 4.0 인 것을 확인했다.
- **면** = Sketchfab `faceCount`(삼각형 수).
- **GLB** = Sketchfab 이 만들어 둔 GLB 파일 크기(원본 텍스처 포함, 줄이기 전). `텍스처 장수@최대 해상도`.
- **계정** = Sketchfab 은 전부 **무료 계정 로그인 필요**(확인). Quaternius · KayKit 은 필요 없음 (확인 못 함 — itch.io 는 기부 창이 뜬다).
- **클립** = Sketchfab `animationCount`. 이름은 설명글에 있을 때만 적었다. "1" 은 동작 여러 개가 한 타임라인에 이어 붙었을 수도 있다 (확인 못 함).
- **실사** = 썸네일 눈대중. 5 = 스캔 수준 · 4 = 사실적 PBR · 3 = 반실사 · 2 이하 = 양식화.
- **주소** = `https://sketchfab.com/3d-models/<id>` (id 만으로 열린다). 표에는 id 만 적은 칸이 있다.
- ★ = 추천.

## 5. 확인 못 한 것

- **각 모델의 클립 이름 · 길이.** "클립 1개" 모델 안에 여러 동작이 이어 붙었는지. → 받은 뒤 `gltf-transform inspect`.
- Sketchfab 이 만든 GLB 에 뼈대가 그대로 들었는지, 뼈 이름(Mixamo 여부).
- **모델 페이지 화면**에서 라이선스를 직접 본 것은 아니다. 공개 API 값과 설명글로 확인했다. 받는 날 페이지에서 한 번 더 본다(WildMesh 늑대처럼 표시가 다를 수 있다).
- Blight Queen 변종 중 Fireborne · Amethystine 외(Pale · Ashen · Vampirical)의 라이선스는 검색 목록 표시만 봤다.
- Free Skeleton Warrior Arrow(@RosserMan) · Fat Zombie(@3d.dreamwork)가 원작자 작품인지 — 설명이 비어 있다.
- cultist(@bumstrum, "Blood" 교도 리메이크)가 원작 디자인 권리에 걸리는지 — 법률 판단은 하지 않았다.
- Quaternius Universal Animation Library Standard 판의 정확한 클립 목록 · 파일 크기 · 받을 때 계정 필요 여부. 우리 후보 뼈대와 리타깃이 잘 되는지.
- Quaternius Ultimate Animated Animal Pack 에 늑대가 있는지.
- KayKit Skeletons 의 삼각형 수 · 파일 크기.
- Sketchfab zip 의 `license.txt` 권장 문구 형식.
- balrog demon rig 에 날개가 있는지, 클립이 정말 없는지.
- 스킨 메시에 `gltf-transform --simplify` 가 안전한지.
- three 예제 `webgl_instancing_morph` 파일 내용 (API 는 r185 소스로 확인).
- 성능 수치(스킨 60마리의 호출 · FPS, 모프 26장 셰이더 비용)는 **추정**이다. 1.4 단계 2 에서 잰다.
- 실사 점수는 썸네일 기준이다. 쿼터뷰 거리(화면 60~100px)에서 어떻게 보일지는 받아서 봐야 안다. 너무 작아 차이가 적으면 보스 · 정예부터만 쓴다.
- Mixamo 로 자동 리그만 한(애니메이션 없는) 모델의 뼈대 배포가 Mixamo 약관에 걸리는지.
- Sketchfab 매각(2026-08, 배경 문서 2.2) 뒤에도 무료 받기가 계속될지 → 쓸 것은 일찍 받아 보관한다.
- Smithsonian 3D 에 쓸 만한 거미 · 늑대 스캔이 있는지 (찾지 못함).
- Poly Pizza 는 따로 보지 않았다.
