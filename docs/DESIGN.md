# 배도라지RPG — 설계서

> 게임 설계의 정본. 규칙·수치가 바뀌면 여기를 먼저 고친다. 개발 상태는 [../HANDOVER.md](../HANDOVER.md), 결정의 근거는 [PLAN.md](PLAN.md).
> 배도라지 덕에서 그대로 가져온 부분(전투 손맛·넷코드·렌더)은 덕의 `docs/DESIGN.md` 가 원본이고, 여기에는 **달라진 것**과 **새로 생긴 것**을 적는다.

## 1. 정체성

- 쿼터뷰 **슈팅 RPG**. 몬스터 무리를 직접 겨눠 쏘아 쓸고, 전리품을 줍고, 캐릭터를 키운다.
- 혼자 ~ **최대 4인 협동**(PvE). PvP 는 배도라지 덕에서 한다.
- 어두운 던전(디아블로·다키스트 던전풍). 캐릭터는 덕의 둥글둥글한 오리 그대로 — 대비가 곧 분위기다.

## 2. 결정론 규칙 (반드시 지킬 것)

`src/core/` 는 모든 브라우저가 같은 입력으로 **완전히 같은 결과**를 내야 한다(락스텝). 덕의 규칙을 그대로 따르고 한 줄을 더한다.

1. `Math.sin/cos/atan2/random`, `Date.now`, `performance.now` 금지. 삼각함수는 `fixedmath.ts`(1024단계 테이블), 난수는 `rng.ts`(mulberry32).
2. 렌더·DOM·오디오를 import 하지 않는다.
3. 플레이어의 의사(캐릭터 교체·줍기·장착·스킬)는 반드시 `Input` 에 실어 보낸다. UI 가 상태를 직접 바꾸지 않는다.
4. 맵은 시드로 생성한다. 부서지는 타일의 정본은 `GameState` 쪽이다.
5. 부동소수 연산 순서를 바꾸지 않는다(반복 순서도 상태의 일부다).
6. **새 규칙: 몬스터·스킬·아이템의 모든 기억과 추첨은 `GameState` 안에서.** 덕의 봇은 기억이 상태 밖에 있어서 방장이 입력을 대신 보냈다.
   몬스터 수백 마리의 입력은 보낼 수 없으므로, 스냅샷만 받으면 누구나 같은 결과를 내도록 전부 상태에 둔다. 상태 밖 캐시는 **상태만으로 다시 만들 수 있는 것**(길찾기 흐름장처럼)만 허용한다.

검증: `tests/determinism.test.ts`.
